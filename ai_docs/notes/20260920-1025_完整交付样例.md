# CrazyLuna 完整交付样例

本文件仅供维护 Skill 或需要理解交付写法时按需阅读，日常调用无需加载。样例展示小任务的方案与启动 Prompt 如何衔接；章节、任务数量和模型选择不构成通用要求。实际规则以仓库中的 `skills/crazy-luna/SKILL.md` 和 `references/models.md` 为准。

以下项目、需求、基线及宿主条件均为虚构教学场景，没有创建或执行该项目，也没有真实测试、模型派发或验收结果。代码和 Prompt 只演示交付内容，不能直接用于当前仓库。真实交付必须改用查证后的项目信息。

## 一、示例输入

用户请求：

> 修复标签清理函数：去掉标签首尾空白后，过滤空标签；保留其余标签的顺序、大小写和重复项，不修改输入数组。只接受字符串数组，非法输入仍抛 TypeError。请先制定方案并给出启动 Prompt，实现和验收都使用 gpt-5.6-luna，medium。

本例设定：

- 项目为 `/workspace/tag-utils`，使用现有 Node.js 环境和 `node:test`，不安装依赖。
- 项目规则要求方案存入 `ai_docs/notes/`、执行记录存入 `ai_docs/logs/`。
- 宿主已确认支持 `collaboration.spawn_agent`，接受 `model`、`reasoning_effort`、`fork_turns` 和 `message`；本例宿主允许串行派发实现与独立验收，剩余子 Agent 名额为 1。此条件是样例设定，不代表实际宿主具有该能力。

## 二、示例交付：方案文档

方案位置：`/workspace/tag-utils/ai_docs/notes/20260920-1000_标签清理方案.md`，版本 v1。以下内容构成该示例方案。

### 目标与事实基线

权威需求为本文“示例输入”中的完整用户请求，在正式方案中原文保留。需求编号如下：

- R01：先去除每个标签首尾空白，再过滤空字符串。
- R02：保留非空标签顺序、大小写和重复项，返回新数组，不修改输入。
- R03：输入须为字符串数组；非数组或含非字符串元素时继续抛 `TypeError`。

仅修改 `src/normalize-tags.mjs` 和 `test/normalize-tags.test.mjs`。不调整导出、依赖或其他功能。方案及执行记录按上述项目规则保存，由协调者维护。

本例项目无 Git，规划时相关文件无已知在途修改。`src/normalize-tags.mjs` 的完整基线为：

```js
export function normalizeTags(tags) {
  if (!Array.isArray(tags) || Array.from(tags).some(tag => typeof tag !== 'string')) {
    throw new TypeError('Expected an array of strings');
  }
  return tags.map(tag => tag.trim());
}
```

现有测试通过公共导出调用该函数，覆盖普通 trim、非数组、非字符串元素及稀疏数组。当前缺口是 trim 后的空字符串仍留在结果中。执行者开工前重新读取两个文件并保存原始内容快照；若实现与上述基线不同，先判断是否影响方案。

本样例没有附测试运行证据，测试结果待执行阶段获取。产品行为没有待决策项。

### 实施设计与任务

保留输入校验、错误类型和导出。对现有 `map` 的结果过滤空字符串，不做排序、去重或大小写转换。在现有测试文件中补充对应断言。

| 任务 | 输入与交付物 | 范围、步骤和依赖 | 角色与验证 |
| --- | --- | --- | --- |
| T01 修复与自测 | R01–R03、现有实现和测试；交付两文件差异与自测结果 | 无前置任务；实现者唯一写入两个业务文件，按上述设计修改并扩展测试 | 实现者；在项目根目录执行 `node --test test/normalize-tags.test.mjs`，覆盖 AC01–AC05 |
| T02 独立验收 | 本方案、T01 前后快照、冻结版本和自测证据；交付逐项 AC 结论 | 依赖 T01 完成并停止写入；读取实际文件和差异，不修改验收对象 | 新建独立上下文的验收者；重新运行同一命令，并核对需求覆盖及修改范围 |

实现者与验收者均请求 `gpt-5.6-luna`、`reasoning_effort: medium`、`fork_turns: none`，依据是用户明确指定，以及本例宿主设定的支持情况。请求型号与宿主实际回报分开记录，未回报实际型号时记未知。不自动替换模型；指定参数无法满足时暂停受影响任务。

协调者只维护方案和执行记录，统一派发及处理返工。T01、T02 串行；两次派发均传入完整任务卡、权威需求、方案位置及必要文件信息，T02 额外传入冻结版本和前后快照。实际执行前复核宿主接口及派发前提；若与本例设定不同，重新适配，无法派发的环节交接手动会话，不声明自动执行就绪。

### 验收标准

共同前提：在 `/workspace/tag-utils` 使用现有 Node.js 环境，从公共导出调用 `normalizeTags`；新增行为断言写入现有测试文件。

| AC | 需求／任务 | 输入或核对操作 | 预期与证据 |
| --- | --- | --- | --- |
| AC01 | R01／T01、T02 | 输入 `[' A ', '', '  ', '\t', 'B']` | 返回 `['A', 'B']`；对应断言及测试输出 |
| AC02 | R02／T01、T02 | 输入 `[' b ', 'A', 'b']` | 返回 `['b', 'A', 'b']`；顺序、大小写及重复项保留 |
| AC03 | R02／T01、T02 | 将冻结的 `[' A ', ' ']` 作为输入，比较调用前后内容和结果引用 | 返回 `['A']`；输入不变，结果与输入不是同一数组 |
| AC04 | R01、R03／T01、T02 | 输入空数组、全空白数组；另分别输入 `null`、字符串、`[1]` 和稀疏数组 | 前两项返回新空数组；非法输入均抛 `TypeError`；保留既有测试 |
| AC05 | 范围约束／T01、T02 | 对比开工快照、最终文件与测试结果 | 业务差异仅在两个授权文件；原校验、导出及其他文件不变；全部相关测试通过 |

独立验收者检查这些标准是否完整覆盖原始请求，记录每项结论、实际命令、退出码和输出。未执行的检查标为未验证，不填写预期的 PASS。

### 执行记录与完成条件

执行记录位置为 `/workspace/tag-utils/ai_docs/logs/20260920-1000_标签清理执行.md`，由协调者在执行开始时创建或续用，规划阶段不创建空记录。

记录任务 ID、负责人、请求与实际模型、状态、产物版本、证据及阻塞原因。T01 自测完成后进入 VERIFYING；T02 独立验收通过并提供证据后，才将相关任务置为 PASS。失败进入 REWORK，缺条件进入 BLOCKED。

T01 回报后停止写入。协调者保存两个文件的内容快照和 SHA-256，作为 T02 的验收版本。返工后重新冻结并验收受影响 AC；最终交付时再次核对版本、范围和全部 AC，证据齐全才宣布完成。

实现者回报任务 ID、修改文件、具体行为、验证命令与结果、剩余问题。重复失败无新证据、设计前提失效或需要扩大范围时，由协调者处理并暂停受影响工作，不扩大范围或降低标准。中断续接时先核对方案、记录、实际文件和在途 Agent，避免重复派发。

本轮实施范围为 R01–R03，对应 T01、T02；首批任务为 T01。业务阻塞为无；执行时仍需复核 Node.js 环境、工作区基线及宿主条件。当前仅为方案就绪，尚无实施或验收结果。
