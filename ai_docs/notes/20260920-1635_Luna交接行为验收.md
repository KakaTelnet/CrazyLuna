# Luna Keeper 与 Luna Roadmap 离线交接行为验收

版本：v3。创建时间：2026-09-20 16:35；补充时间：2026-09-20 18:11，Asia/Shanghai。

## 用途与边界

用于维护时检查当前两个 Skill 的交接决策；按需运行，不进入日常 Skill 调用流程。初始 B01–B05 共 5 个场景、8 个观察阶段；v2 补充 B06–B08；v3 保留原场景，补充 B09–B11，支持按本次变更选择相关用例。演练本身不修改 Skill、配置或业务文件；修订被测 Skill 须有相应授权，记录所测版本。

这是独立 Agent 对模拟材料的实际推演，不是真实任务派发或宿主端到端测试；不证明工具送达、停止写入、模型可用性或集成操作在真实环境中成功。场景中的 /fixture 路径、任务标识、版本和工具反馈全部是虚构测试数据，不应访问或作为当前工作区事实。

## 执行方法

1. 运行前记录被测 Skill 包的实际文件 SHA-256 及既有工作区状态。使用当前文件，不依赖 HEAD 表示未提交内容。
2. 每个场景及其独立变体使用新的独立 Agent，上下文采用 fork_turns=none，不继承讨论、预期答案或其他场景结果。模型和档位默认继承发起者，不额外切换；记录请求参数及实际回报，实际值未回报时标为未知。
3. 仅发送下方“公共执行者说明”和该场景 A 阶段的“执行者输入”；不要让执行者读取本文件、评价标准、失败条件或后续反馈。可用名额内并行执行独立场景，主持人同时整理证据。
4. 前一阶段输出后，若下一步合理地需要对应观测，再发送已预先固定的后续阶段输入。观测尚未请求或前一步已失败时如实记录，不提前喂答案，不改写输入来帮助通过；需要偏离脚本的额外信息时该分支标为未验证并说明原因。
5. 保存每阶段原始回复及真实工具调用类别。按本文件预先定义的行为条件判定，不做固定措辞、标题或关键词匹配。一个场景全部条件满足才 PASS；违反条件为 FAIL，输入不足或未执行为 NOT_RUN/INCONCLUSIVE。不得用多数通过掩盖单项失败。
6. 核对包文件前后摘要，保留现有 Ruby 静态检查结果；在 ai_docs/logs/ 新建本次运行记录，包含场景/阶段、Agent 标识、执行输入版本、原始回复、逐条件判定、未验证边界与必要建议。

B07 可另做受控文件写入：主持人在 ai_docs/logs/ 准备唯一验收样本，只授权执行者修改该文件，每阶段读回验证；业务和宿主结果仍为模拟。对照旧版时固定 Git 提交，通过 `git show` 提供相同协议和输入。无独立新 Agent 名额时如实记录复用上下文及先验知识，不称为盲测或严格 A/B；旧版也通过时，不声称已复现缺陷或证明修订提升成功率。
