# CrazyLuna 跨工具模型配置与验证

时间：2026-09-10 19:55，Asia/Shanghai。

## 当前需求与实现

支持 Codex、Claude Code、WorkBuddy 等工具的规划与交接；在一个 reference 中配置多个候选模型，由规划者选择；首次手动运行识别当前可用模型并保存默认值。保留用户手动调用、独立验收、范围及版本绑定边界。

采用共享模型清单与本机识别结果分开保存的方案。候选清单没有被本机识别结果覆盖，不绑定用户账号；这次维护验证也没有调用业务规划流程、切换主模型或创建 Goal。

| 文件 | 作用 |
| --- | --- |
| skills/crazy-luna/SKILL.md | 跨工具入口、首次识别步骤、通用派发模板；新增 disable-model-invocation: true |
| skills/crazy-luna/agents/openai.yaml | 通用 UI 文案，保留 Codex allow_implicit_invocation: false |
| skills/crazy-luna/references/models.md | 唯一可编辑候选清单、模型 ID 解析、选择、持久化及宿主差异规则 |
| .crazy-luna/models.local.json | 本次根据当前 Codex 派发 schema 识别并写入的本地默认值 |
| .crazy-luna/.gitignore | 忽略 models.local.json，避免把本机结果随 Git 分发 |

默认候选：gpt-5.6-luna、claude-haiku、deepseek-v4.1-flash。后两者是 reference 中的候选标识，分别按当前宿主解析为 Haiku 请求 ID、DeepSeek V4.1 Flash 请求 ID；当前官方 DeepSeek API ID 为 deepseek-flash。不把候选清单视为账号可用性证明。

模型选择优先级为当前用户指定、reference 允许池与固定/自动默认规则；任务能力是选择前提。临时指定不覆盖长期默认。推理默认为中度偏好，实际参数遵循当前模型和接口，不统一硬传 medium。

## 当前默认值的实际识别与写入

当前会话的 collaboration.spawn_agent schema 明确暴露 gpt-5.6-luna，并支持 medium；reference 的另两个候选未在本轮派发接口中暴露。与候选清单匹配后，实际保存：

```json
{
  "host": "codex",
  "status": "ready",
  "dispatch_supported": true,
  "default_model": "gpt-5.6-luna",
  "reasoning_preference": "medium",
  "reasoning_parameters": {"reasoning_effort": "medium"},
  "runtime_model": null
}
```

以上是记录字段摘要，真实文件按 hosts.codex 保存，并包含候选、来源、选择原因及检查时间。记录只声明当前接口允许派发，没有将请求型号写成宿主已确认的实际运行型号。没有读取或保存第三方密钥。

通过 Ruby 标准库解析 reference YAML、匹配当前接口声明、写入 JSON，并再次根据相同证据核对；第二次选择维持默认值，不重写记录。没有为自动识别新增运行依赖或全局配置；Skill 使用调用它的 Agent 已有文件与宿主工具执行这些步骤。

## 验证结果

1. Ruby YAML/JSON 检查：退出码 0。名称、描述长度、两个手动策略、候选列表、固定默认合法性、reference 链接、围栏、空白与本机默认值均通过。由于使用宿主扩展 frontmatter，不宣称原版 Python quick_validate.py 已通过；本轮未执行 Python。
2. 安装内容检查：对运行包三文件使用 File.binread 比较实际字节，安装路径与项目文件一致。首次检查误混用二进制/文本编码，纠正比较方式后通过，文件无需修改。
3. Codex 原生加载：本机 app-server 的 initialize → initialized → skills/list 返回 crazy-luna，scope=user、enabled=true、errors=[]，路径指向本项目 SKILL.md。证明当前 Codex 能加载带扩展 frontmatter 的运行包，不代表所有版本均可加载。
4. 当前默认值写入和复用：真实 JSON 存在，默认处于当前可派发候选中，记录不包含秘密，忽略规则存在；相同证据复核输出 KEEP。
5. 独立只读审查：/root/review_portable_policy 读取最终运行包，以七组宿主与模型情景推导规则；修正边界后，最终结论为没有影响当前需求的明确冲突。审查者未调用本 Skill，也未修改文件。

Codex 原生加载测试首先受沙箱影响，无法初始化本机 SQLite 状态。随后将 SQLite 目录通过临时配置指向 /private/tmp/kcrazy-luna-portable-BKT45F/sqlite，并经自动审批允许在沙箱外进行限定的只读加载检查，最终退出码 0。未修改用户 config.toml，没有创建任务或执行模型。测试请求是：

```json
{"id":1,"method":"initialize","params":{"clientInfo":{"name":"crazy-luna-local-load-check","version":"1.0"},"capabilities":{"experimentalApi":true}}}
{"method":"initialized","params":{}}
{"id":2,"method":"skills/list","params":{"cwds":["/Users/kaka/kDevelop/Skills/kCrazyLuna"],"forceReload":true}}
```

临时进程启动参数为 codex app-server --stdio -c 'sqlite_home="/private/tmp/kcrazy-luna-portable-BKT45F/sqlite"'；响应后已停止进程。

| 情景 | 验证范围与结果 |
| --- | --- |
| Codex 只暴露 Luna/medium | 当前真实接口识别并保存默认，通过 |
| Claude Code 暴露 haiku、无 effort | 规则推导为 haiku、不传 effort，静态通过 |
| WorkBuddy 仅主选择器有 DeepSeek、无子 Agent 接口 | 不把主模型列为可派发候选；默认 null，仅提供手动交接，静态通过 |
| 无当前模型清单 | unknown、默认 null，不凭公开目录猜测，静态通过 |
| 用户仅指定更强验收模型/推理 | 只覆盖本轮对应角色，不改长期默认，静态通过 |
| 多宿主记录、固定默认失效或损坏 JSON | 保留其他宿主；失效默认 null；损坏时阻塞写入但可在内存规划，静态通过 |
| 多候选、任务需要图片 | 仅选择有当前所需能力证据的候选，静态通过 |
